# Codex art request v3: high-resolution characters at double frame count

Requested by Claude Code on 13 October 2026 after the owner's review ("the main
characters look a bit low-res, and the animation has few frames"). Execute with the
built-in **GPT Imagegen** skill. Machine-readable job list:
[prompts/jobs-v3-characters.json](prompts/jobs-v3-characters.json) (185 jobs, generated by
`python3 tools/art/make_v3_jobs.py`). Sources stay immutable in `art/source/`; Claude
does all extraction, packing and animation wiring afterwards.

## 1. Why

| Measure | Current (v1/v2 sheets) | Target (v3) |
|---|---|---|
| Frames per character | 16 (4 reactions × 4) | **32** (4 reactions × 8) + 4 optional talk frames |
| Playback rate | 3.5–7 fps | 7–14 fps at the same reaction durations |
| Measured frame size | 241–305 px wide, 255–305 px tall | each frame generated alone on a ≥ 1024 px canvas; subject ≈ 78 % of canvas height |
| Largest on-screen use | quest intro ≈ 500 CSS px tall = 1000 device px on a retina iPad (≈ 3.3× upscale today) | ≤ 1× upscale on the intro after packing |

The old sheets packed 16 frames into one 1254 × 1254 image (the tool ignored the 2048 request),
so each frame only got ≈ 300 px. **The fix is one frame per image.** Identity and registration
consistency come from generating every frame as an *edit of one master frame*, not from
putting all frames into one picture.

## 2. Deliverables

For each character id in `bill`, `tiny`, `mazu`, `rocky`, `giganto`:

```text
art/source/character-<id>-v3/
  master.png            the approved neutral frame (also copied to idle-00.png)
  idle-00.png … idle-07.png
  drawing-08.png … drawing-15.png
  encouragement-16.png … encouragement-23.png
  celebration-24.png … celebration-31.png
  talk-32.png … talk-35.png        (priority 2, optional)
```

- PNG, RGBA, **true alpha** (inspect in a browser on a dark background; the generator preview
  has shown RGB under transparent pixels before).
- Every file in a character folder has **the same canvas size** (largest square the tool
  supports, 2048 preferred, never below 1024).
- Update `art/manifest.json` with one entry per folder: canvas size, frame count, sha256 per
  file, prompt file, status `source-candidate-runtime-qa-pending`.

## 3. How to generate (order matters)

1. **Masters first (5 jobs, priority 1).** References: `references/gigantosaurus-cast.png`
   (identity) and `review/runtime/<id>-frame0.png` (current pose, crop and angle; exported from
   the game). Generate 2–3 candidates per character and keep the one closest to the TV design.
   *Stop and send the five masters to the owner for likeness sign-off before step 2*; every other
   frame inherits the master's face.
2. **Key frames** (even numbers in the table below), each an edit of the image named in the
   "edit of" column, which is the master or another key.
3. **In-betweens** (odd numbers), each an edit of its key. If the tool accepts two input images,
   pass both neighbouring keys and ask for "exactly halfway between image 1 and image 2".
4. **Talk loop** (priority 2) last.

Prompt rules already baked into every job: identity paragraph per character, transparent
background, upper-body bust cut at the waist on the bottom edge, 11 % headroom above the highest
point (crest, plume, frill), warm upper-left light, no text/scenery/props/floor shadow, and
"re-illustrate cleanly; do not cut pixels out of the reference photo" (the Tiny v1 lesson).

## 5. Codex self-check before handing over

- [ ] Five masters approved by the owner for likeness (record the date in `art/manifest.json`).
- [ ] Same canvas size for every file of a character; nothing touches a canvas edge except the
      waist crop on the bottom edge.
- [ ] Head width and eye positions within ±2 % of the master across all frames (overlay at 50 %
      opacity on the master to check). No drifting markings, extra fingers, or changed horn,
      crest, frill or plume shapes.
- [ ] Alpha clean on cream and on dark green: no halo, no leftover foliage, no checkerboard.
- [ ] GIF preview per reaction at 10 fps (`art/review/v3/<id>-<reaction>.gif`) reviewed in motion;
      in-betweens really sit between their keys (no pops).
- [ ] Prompts and any revision prompts saved under `art/prompts/` next to the job list.

## 6. What Claude does after delivery

- Extend `tools/art/extract.py` for single-frame sources: measure and register every frame to
  the master, trim transparent padding, and pack **trimmed atlases** (Phaser supports trimmed
  frames with a source size, so padding costs no GPU memory).
- Two size tiers to stay inside the 96 MiB GPU budget: a corner tier (≈ 512 px frame height)
  for play, and a stage tier (≈ 900 px) used only for the quest intro pose. Load each friend's
  full set only when it hosts a maze; the welcome cast uses idle frames only.
- Double the animation frame rates in `src/game/actor.ts` (same durations), add the talk loop
  while the speech bubble is visible, regenerate the review GIFs, and re-measure memory and
  first-playable time against PRD §9.
